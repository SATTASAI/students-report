# ระบบรายงานผลการเรียน โรงเรียนบ้านป่าเด็ง (students-report)

เว็บไซต์: https://grades.banpadengschool.ac.th

ระบบบันทึกคะแนนและรายงานผลการเรียนระดับ ป.1–ป.6 ทำงานเป็น Cloudflare Worker ตัวเดียว ใช้ฐานข้อมูล D1 และบัญชีผู้ใช้ร่วมกับระบบบริหารโรงเรียน (banpadeng-school-db)

## ความสามารถ

- **ครูผู้สอน** ตั้งโครงสร้างคะแนนตามตัวชี้วัดได้ 3 วิธี คือพิมพ์เอง วางจากเอกสารหลักสูตร หรือเลือกจากคลังตัวชี้วัด และคัดลอกโครงสร้างจากห้องอื่นได้
- **สมุดคะแนน** เป็นตารางแบบ Excel กด Enter เพื่อเลื่อนลงไปคนถัดไป วางช่วงคะแนนจาก Excel ได้ บันทึกอัตโนมัติ และกันคะแนนเกินเต็มหรือไม่ใช่ตัวเลข
- **ตัดเกรดรายปี** 8 ระดับ คะแนนรวมไม่ปัดเศษ (79.99 ได้ 3.5) สัดส่วนคะแนนเก็บกับปลายภาคตั้งแยกรายวิชาได้
- **ผลพิเศษ** เวลาเรียนไม่ถึง 80% ได้ มส อัตโนมัติ คะแนนไม่ครบได้ ร บันทึกสอบแก้ตัวได้ (แก้ 0 หรือ มส ได้สูงสุด 1) และบันทึกเรียนซ้ำได้
- **ตัวชี้วัดไม่ผ่าน** ระบบแสดงและเตือน แต่ไม่บล็อกการให้เกรด
- **ยืนยันผล** แล้วรายวิชาจะถูกล็อก ผู้ดูแลปลดล็อกได้
- **ครูประจำชั้น** ประเมินคุณลักษณะอันพึงประสงค์ 8 ข้อ, การอ่าน คิดวิเคราะห์ และเขียน, สมรรถนะ 5 ด้าน และกิจกรรมพัฒนาผู้เรียน บันทึกวันขาดเรียนของเด็กที่ขาดบ่อย และพิมพ์หนังสือแจ้งผู้ปกครองได้
- **เอกสาร** ปพ.5, ปพ.6, ปพ.1 (ฉบับตรวจทาน), รายงานสรุปผลสัมฤทธิ์ และหนังสือแจ้งขาดเรียน สั่งพิมพ์หรือบันทึกเป็น PDF ได้ และเลือกใช้เลขไทยได้
- **ส่งออก** เป็น Excel รายห้องหรือทุกห้อง และ CSV แบบ 1 แถวต่อ 1 วิชา

## ติดตั้งครั้งแรก

1. **สร้าง Worker จาก repo นี้** ใน Cloudflare ไปที่ Workers & Pages → Create → Import a repository → เลือก `SATTASAI/students-report` แล้วตั้งชื่อ Worker ว่า `students-report`
2. **ตั้ง secret `JWT_SECRET`** ที่ Worker → Settings → Variables and Secrets → Add → ประเภท Secret ชื่อ `JWT_SECRET` ค่าต้อง**เหมือนกับ** `JWT_SECRET` ของ banpadeng-school-db ทุกตัวอักษร
3. **ไม่ต้องผูก D1 เอง** เพราะประกาศไว้ใน `wrangler.jsonc` แล้ว (`DB` → `banpadeng_school_db`)
4. เปิดเว็บแล้วเข้าสู่ระบบด้วยบัญชีผู้บริหาร ระบบจะสร้างตาราง `gr_*` ให้เองตอนที่ใช้งานครั้งแรก
5. ไปที่ **ตั้งค่ารายวิชา → เริ่มต้นปีการศึกษา** แล้วทำตามขั้นตอนที่หน้านั้นแสดง

> ถ้าหน้าเว็บขึ้นว่า "ยังไม่ได้ตั้งค่า JWT_SECRET ของ Worker" แสดงว่ายังไม่ได้ทำขั้นตอนที่ 2

## ข้อมูลที่ใช้ร่วมกับระบบบริหารโรงเรียน (อ่านอย่างเดียว)

| ข้อมูล | ตาราง |
|---|---|
| บัญชีผู้ใช้ / สิทธิ์ | `users` (superadmin, executive ถือเป็นผู้ดูแลโดยอัตโนมัติ) |
| ปีการศึกษา / ภาคเรียน | `academic_years`, `academic_terms` |
| นักเรียน / ห้องเรียน | `students`, `student_details`, `student_enrollments` (ใช้ภาคเรียนล่าสุดของปี) |
| ครูประจำชั้น (ดึงครั้งแรก) | `learner_class_assignments` |

ระบบนี้**เขียน**เฉพาะตารางที่ขึ้นต้นด้วย `gr_` เท่านั้น ยกเว้น 3 จุดที่ใช้ร่วมกับ school-db:
- `system_settings` เก็บเลขเวอร์ชันของตารางไว้ 1 แถว (`students_report_schema`)
- `auth_login_throttles` นับจำนวนครั้งที่ล็อกอินผิด ใช้ร่วมกับ school-db
- `users.last_login_at` อัปเดตทุกครั้งที่เข้าสู่ระบบ

ตาราง `gr_` ไม่มี foreign key ชี้ไปยังตารางของระบบบริหารฯ จึงไม่ทำให้การลบผู้ใช้หรือนักเรียนในระบบนั้นล้มเหลว

## ก่อนเปิดภาคเรียนที่ 2

- จัดชั้นเรียนภาคเรียนที่ 2 ในระบบบริหารโรงเรียนก่อน รายชื่อในสมุดคะแนนจะเปลี่ยนตามภาคเรียนล่าสุดเอง ถ้ายังไม่จัด ระบบจะใช้รายชื่อของภาคเรียนที่ 1
- นักเรียนที่ย้ายออกหรือย้ายห้องระหว่างปีจะไปอยู่ท้ายตาราง ไม่มีเลขที่ แต่คะแนนเดิมยังอยู่ครบ

## พัฒนาและทดสอบบนเครื่อง

```bash
npm test                 # ทดสอบกติกาตัดเกรดและ API (node:test + node:sqlite แทน D1)
npm run dev              # เปิด http://localhost:8787 พร้อมข้อมูลสมมติ (รหัสผ่าน test-password-1)
dev/run-e2e.sh /tmp/out  # ทดสอบหน้าเว็บด้วย Playwright และเก็บภาพหน้าจอ/PDF
```

บัญชีทดสอบ: `admin@test.local`, `teacher1@test.local`, `teacher2@test.local`

```
public/print/         หน้าพิมพ์ ปพ.5, ปพ.6, ปพ.1, สรุปผล, หนังสือแจ้งขาดเรียน
```
